## 与报告一致的十二表

users、admins、addresses、products、product_images、orders、conversations、messages、refunds、reviews、reports、favorites。

报告的 users/admins 本来就有 password_hash，因此 v4 不是额外增加一个业务概念。v3 文档因未见报告原件而标记的“未逐字段核对”，在本轮已完成关系字段核对。

## 有意保留的实现差异

- INT 自增主键替代 SQLite INTEGER PRIMARY KEY；文本字段按用途使用 VARCHAR/TEXT/MEDIUMTEXT。金额保持整数分，时间保持北京时间文本。
- `orders.active_product_id` 是技术生成列，用唯一索引限制同一商品的有效订单，不是额外业务属性。
- `conversations.pair_low/pair_high` 是技术生成列，唯一限制双方无序组合；实际 initiator_id 保留谁先发起。v3 已经把历史双方排序，迁移不能恢复丢失的发起者信息。
- 同一订单最多一次退款；每位交易参与者每订单一次文字评价。报告没明确退款重试次数，本版沿用既有课程规则。
- 原始七件商品和五个订单保留；演示种子另外保留六件商品用于页面展示与测试，非原报告新增实体。
- 报告描述议价；本项目支持聊天协商，但订单使用下单时商品标价，没有买家提交任意成交价或议价改价审批功能。原始订单样例的成交价与标价不同，作为历史快照保留。
- 自提交付由卖家确认后完成；真实资金、物流和退货安排仍不接外部服务。

## 约束补齐

MySQL schema 与升级脚本补齐用户状态、快递收件信息非空、自提零运费、退款状态、举报状态约束，并允许报告中的“未提交”审核状态。界面发布流程仍直接提交待审核，没有新增保存未提交草稿按钮。
